PocketBase Dashboard

Collections, records, API rules and filters: a backend in one file Upstream projectInstall and test code

A working model of the PocketBase superuser dashboard over example collections held in this page. Field types are PocketBase's own (core/field_*.go), filters and API rules follow its filter syntax, ids are 15 characters and dates use its layout "2006-01-02 15:04:05.000Z". Sandbox-2 runs the real binary, built from source, on port 8095.

Collections /

Locked (no rule) means superusers only; an empty rule means anyone; otherwise the filter must match. Edit a rule to see who passes.

Query contracts

This page accepts @now plus a whole number of days written as "90d" for the renewal window; real PocketBase compares @now with a date stored on the record or sent in the request.

Subscriptions

        
PocketBase streams changes over Server-Sent Events at /api/realtime. A client connects, receives PB_CONNECT with its clientId, then posts the topics it wants. Create, update or delete records on the Collections tab to see the events here; the collection's view rule decides who receives each one.

flowchart LR
  C[Clients: JS and Dart SDKs, curl] -->|REST /api| R[Router and middlewares]
  C -->|SSE /api/realtime| RT[Realtime broker]
  R --> A[Auth: password, OAuth2, OTP, MFA]
  R --> RR[Record API: list, view, create, update, delete]
  RR --> RU{API rules: filter expressions}
  RU --> DB[(SQLite in WAL mode: pb_data)]
  RR --> FS[(Files: local or S3)]
  H[Go hooks or pb_hooks JS] --> RR
  RR --> RT
  UI[Superuser dashboard: Svelte, embedded] --> R

  Cl->>PB: GET /api/collections/contracts/records?filter=...

  DB-->>PB: rows
  PB->>PB: expand relations the caller may view
