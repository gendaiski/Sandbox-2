A model of the Appwrite 2.6.2 console over an example project held in this page. Column types are the TablesDB ones in src/Appwrite/Platform/Modules/Databases, queries serialize the way the SDKs send them, and permissions use Appwrite's role strings. Sandbox-2 runs the real self-hosted Appwrite from its own installer on port 8096.

Services in docker-compose.yml


flowchart LR
  B[Browser, SDKs, CLI] --> T[traefik]
  T --> API[appwrite: HTTP API]
  T --> CON[appwrite-console]
  T --> RT[appwrite-realtime: WebSocket]
  API --> DB[(mariadb, mongodb or postgresql)]
  API --> R[(redis: cache and queues)]
  R --> W[workers: databases, functions, builds, mails, messaging, webhooks, deletes, migrations, usage]
  W --> EX[openruntimes-executor: functions and sites]
  API --> CH[(clickhouse: usage and logs)]
  SCH[task schedulers: functions, executions, messages, maintenance] --> R


      
Reading a row


flowchart TB
  Q[GET rows with queries] --> K{API key?}
  K -->|yes| ALL[key scopes decide: rows.read]
  K -->|no| TP{table permission read for one of my roles?}
  TP -->|yes| OK[row returned]
  TP -->|no| RS{row security on?}
  RS -->|yes| RP{row permission read for one of my roles?}
  RP -->|yes| OK
  RP -->|no| X[filtered out]
  RS -->|no| X
