Izwi Voice Studio

Local text to speech, transcription and voice chat behind OpenAI-compatible routes Upstream projectInstall and test code

Izwi runs its models on your own machine, so this page cannot run them; it builds the exact requests Izwi's server takes and plays a preview with your browser's built-in voice instead. The model list is Izwi's own catalog (crates/izwi-model-catalog), printed by a small Rust program against the source. In Sandbox-2's CI the real server ran Kokoro-82M and Parakeet-TDT-0.6B-v3 on a CPU.

What Sandbox-2's CI checked
          
izwi tts "The liability cap is twelve months of fees." wrote a WAV with Kokoro-82M; izwi transcribe read it back with Parakeet-TDT-0.6B-v3, and the transcript had to contain "liability" and "twelve" (or 12). The check passed in 67 seconds on the runner's CPU.

A voice turn: hear, think, speak

        
Izwi's voice mode chains an ASR model, a chat model and a TTS model. Here you type instead of speaking, Claude plays the chat model (on your own Claude account) and your browser's voice speaks the reply.

Crates and apps


flowchart LR
  UI[Web UI and desktop app] -->|/v1 HTTP and WebSocket| S[izwi-server]
  CLI[izwi CLI] -->|--server URL| S
  SDK[OpenAI SDKs] -->|/v1/audio/speech, /v1/audio/transcriptions, /v1/chat/completions| S
  S --> CORE[izwi-core: engine, scheduler, model loading]
  CORE --> CAT[izwi-model-catalog: 46 model variants]
  CORE --> BK[backends: CPU, Metal, CUDA]
  CORE --> HF[(model files from Hugging Face)]

sequenceDiagram
  participant M as Microphone
  participant A as ASR (Parakeet, Whisper, Qwen3 ASR)
  participant C as Chat model (Qwen, LFM2.5)
  participant T as TTS (Kokoro, Qwen3-TTS)
  M->>A: audio frames
  A->>C: transcript
  C->>T: reply text, streamed
