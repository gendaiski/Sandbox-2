## Library, studio and new battle game

The site root is now a categorized library. It contains the four reference-based scenes plus a new **Pokémon Battle** variation. Each card opens the live Three.js studio. The existing toolkit and water/inspection fixtures remain separate.

- `/`: searchable library with category filtering, saved variations and JSON import.
- `/scenes/#game`: playable fan-made battle. Choose Pikachu or Charizard, then Start battle. Use a special attack (6 PP), unlimited physical attack, guard (70% damage reduction), or two potions (up to 36 HP each). The local opponent uses a strong attack every third turn. Easy, Normal and Hard affect enemy damage. Win/loss, a 60-turn draw, battle log and New battle reset are implemented. The game uses simplified rules and newly authored models, not official game assets or official combat rules.
- `/scenes/`: five designs, scene playback controls, orbit/reset, PNG capture, plus Customize: title, daylight/golden/moonlight, pixel/smooth rendering and stage color. Save to the library or export/import design JSON. Individual object editing is not part of this studio.
- `/downloads/diorama-scenes.html`: self-contained studio and game. Native rendering and gameplay need no network. Reference films still need the full ZIP's media folder or the hosted site.

Saved variations and battle win/loss totals use local browser storage. There is no account, server database or cross-device sync. Export design JSON to transfer settings between browsers. Saving does not overwrite built-in scenes. Current fights restart when reloaded or when leaving the game.

Pokémon names refer to an unofficial fan-made mini-game. No official logos, music, sprites or game assets are bundled. Existing MIT notices and toolkit attribution remain intact.

## New interactive scenes

Open `/scenes/` from the library for the newly authored Pool, Bank Job, Dust Kings and creature battle. These reconstruct the supplied recordings using real scene geometry and articulated animation. Source is in `reconstruction/`; source provenance and design choices are recorded there. They are not claimed to be exact or recovered originals. The native canvas never uses the recordings as a background or substitute.

Controls: scene tabs, drag/pinch/wheel orbit, keyboard arrows/R, play/pause, restart, timeline, speed, PNG capture, reference-film dialog and downloadable offline HTML. `OPEN-SCENES.html` in the ZIP runs all four without networking; reference film playback additionally requires the included `media/` folder.

The earlier toolkit gallery remains at `/toolkit.html`. The minimal effects harness is at `/water-test.html`; `/original.html` now opens the actual reconstructed scene viewer.

## What is installed

The complete supplied MIT-licensed toolkit, documentation, templates, verification fixtures, reference media and original water-effects test. This is a Three.js browser toolkit; upstream has no server backend, accounts, scene editor or complete application shell. No backend was fabricated.

- `water-test.html`: the water-effects test generated by the upstream build, with a clear test-only notice and the documented replay fix.
- `water.html`: the same simulation with a new viewer using the supplied orbit helper, play/pause, deterministic timeline, camera reset and PNG capture.
- Rendering lab: the original synthetic inspection fixture, with all three supplied render styles, assembly/piece selection and clear.
- Showcase: the four original films. Complete source for those narrative scenes is absent upstream. They are recordings, not interactive restorations.
- Source library: all supplied guides and modules. Modules are developer building blocks, not hidden end-user screens.
- Download kit: original source, reference media, runnable offline `OPEN-WATER.html`, build scripts and licences. Opening the HTML requires no sign-in or network.

The preview shell is new navigation; the minimal water-effects test remains available separately. Water geometry, materials and choreography are preserved. A small upstream determinism fix resets splash-drop rotations on each burst, preventing previous playback from changing a frozen frame. Both the original view and added viewer include this fix. This is not an animation editor, and no MP4 export feature is claimed.

## Install and run

Node 22 or 24: `npm ci`, `npm test`, `npm run build`.
Serve `dist` using any static server (for example `npm run preview`, which uses Python 3 on port 4185). Vercel: framework Other, build `npm run build`, output `dist`.

Use Chrome, Edge, Firefox or Safari with WebGL2 enabled. Desktop and touch orbit supported. The scenes retain the toolkit’s pixel rendering. Performance varies with GPU. Reduced motion starts the added viewer paused. Source library fetches need HTTP; the included standalone water HTML works directly offline.

## Regression checks

`npm test` supplies local Three module paths to upstream tests, replacing the need for the author's absolute Mac directory. `CHROME=/path/to/chromium node templates/qa/education-dock.test.mjs` tests original controls. `CHROME_PATH=/path/to/chromium DIORAMA_FIXTURE_URL=http://127.0.0.1:4185/inspection.html node templates/qa/inspection-browser.mjs` tests the inspection fixture over HTTP. Linux testing uses SwiftShader. The separate toolkit controls and deterministic rendering are covered by `node scripts/browser-test.mjs` with `BASE_URL` and `CHROME_PATH` overrides.
