The key distinction

Source-reported data, clearly labelled.

Ratings, review counts, badges and benchmark figures shown here are transcribed from the supplied Legal Benchmarks directory snapshot. We checked our transcription against that file. We did not independently verify the underlying reviews, run their benchmark tasks, or certify any product.

01 / Review workflow

Four steps from page to usable directory.

Every displayed claim should trace back to a captured field, a visible screenshot excerpt, or an explicitly named gap.

01 / CAPTURE

Preserve the source

Store the supplied public HTML and record its URL, receipt date and SHA-256 checksum.

02 / EXTRACT

Read structured entries

Parse the page's embedded application data into card, profile and benchmark fields.

03 / RECONCILE

Check the copy

Compare all 22 names, descriptions, use cases, ratings and review counts with the captured entries.

04 / PRESENT

Keep gaps visible

Provide search, filters and profiles. Mark unavailable review text and link back to the original source.

A displayed score is not our verdict.

The copied benchmark figures retain their original publisher's meaning. Our contribution is a traceable, usable presentation of the captured data.

03 / Reading the numbers

A field guide to the cards.

Open any field below to see where it comes from and what it does not establish.

Ratings and review counts

These are published values in the directory snapshot. We checked the values were copied correctly. The underlying review identities and full review texts were not included in the saved directory HTML.

Certifications and badges

These are labels present in the captured source. We show them as source-published badges, not certifications awarded by Website Twin.

Benchmark results

These rows and comparison figures came from embedded source data. For the publisher's testing procedure, read the captured source methodology. We have not rerun its tasks or grading.

Descriptions and use cases

These are copied from the saved public directory data. They describe how the publisher categorised each product at the time of capture, not our own capability testing.

Proposed / Not yet run

A path to an independent evaluation.

These steps describe work we could build next. They have not produced scores or rankings for this directory.

1
Define tasks and scopeDocument practice areas, jurisdictions, file formats and success criteria with qualified reviewers.
2
Obtain lawful test accessConfirm product plans, permissions, privacy terms, costs and any required accounts before testing.
3
Run controlled workflowsUse the same documented inputs and recording procedure; preserve outputs and note product-specific differences.
4
Review with human expertsApply a published rubric, resolve contested assessments and separate legal correctness from interface quality.
5
Publish evidence and limitsShow run dates, versions, failures, uncertainty and appropriate confidentiality controls.
6
Retest changesVersion results and rerun affected tasks when products or evaluation rules change.
Current status: proposal only.

Until the tasks, permissions, results and review process exist, this directory remains a source-backed catalog rather than an independent leaderboard.
